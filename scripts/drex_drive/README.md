# Drex Max в замкнутом контуре

Первый прототип ведёт машину по одной полосе от старта до остановки у цели. По умолчанию решения принимает `nace-ai/drex-max-v1` через штатный Python runtime. DriveSuprim, NAVSIM и их данные для запуска не требуются.

Каждые 0,5 секунды симуляции Drex получает текущую и предыдущую скорость, прошлую команду, расстояние до цели, состояние видимого светофора и скорость и дистанцию до ведущей машины. Модель выбирает `proceed`, `maintain`, `slow`, `stop` или `wait`. Симулятор исполняет команду шагами по 0,1 секунды и передаёт новое состояние на следующий запрос. Аварийное торможение отслеживает дистанцию до ведущего автомобиля. Ошибка ответа вызывает остановку и записывается в журнал. Соблюдение светофора и остановка у цели зависят от решений водителя.

В `route` есть ведущая машина и светофор. `red_light` проверяет светофор на свободной дороге. В `lead_brakes` ведущая машина останавливается и снова трогается.

## Локальная проверка

Из корня репозитория, Python 3.10 или новее. Этот режим использует правила, чтобы проверить сценарий и исполнение команд.

```bash
python -m unittest scripts.drex_drive.test_drive -v
python -m scripts.drex_drive --driver reference --scenario route --out output/drex-drive-reference
```

## Прогон с Drex Max на msu270

Команда использует подготовленные на кластере Python-окружение, официальный runtime и веса. Выполнять из корня репозитория на `msu270`.

```bash
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
drex_run_dir="$DREX_RUNTIME_ROOT/runs/drive-route-$(date -u +%Y%m%dT%H%M%S%NZ)"

srun --partition="${DREX_PARTITION:-batch}" --gres=gpu:1 --cpus-per-task=4 --mem=96G --time=00:30:00 \
  env PYTHONPATH="$DREX_RUNTIME_ROOT/upstream" \
  "$DREX_RUNTIME_ROOT/venv/bin/python" -m scripts.drex_drive \
  --scenario route --model "$DREX_RUNTIME_ROOT/models/drex-max-v1" --out "$drex_run_dir"
```

`trace.jsonl` содержит запросы и ответы модели, состояние автомобиля на каждом шаге и источник каждой команды. `report.json` содержит исход поездки, нарушения, вмешательства, долю шагов под управлением водителя и время вызовов. Код выхода `0` означает финиш с остановкой без нарушений, аварийного торможения и ошибок ответа. Для повторного прогона укажите новую папку.

## Прогон с движением во время инференса

В режиме `--mode realtime` симулятор выполняет шаг каждые 0,1 секунды по настенным часам, а отдельный поток обращается к Drex. Запросы отправляются каждые 0,5 секунды, если предыдущий вызов завершён. Ответ должен быть принят за 0,5 секунды после отправки. Пока результат в пути, действует предыдущая команда сроком до 0,5 секунды с момента её применения. По истечении срока команды или запроса симулятор тормозит. Запоздалый ответ записывается в журнал, а следующий запрос использует свежее наблюдение.

На msu270 из корня репозитория запусти `bash scripts/drex_drive/submit.sh warm route`. Один запрос до начала поездки прогревает GPU и учитывается отдельно в `warmup_wall_s`. Для замера холодного старта используй `bash scripts/drex_drive/submit.sh cold route`. После `Submitted batch job` можно отключиться от SSH.

Для номера задания `JOB_ID` лог находится в `$DREX_RUNTIME_ROOT/logs/drive-rt-JOB_ID.log`, а отчёт и события — в `$DREX_RUNTIME_ROOT/runs/drive-rt-JOB_ID/`. Если `DREX_RUNTIME_ROOT` не задан, скрипт берёт `/scratch/pr0201/drex_runtime`.

В отчёте `decision_applied` считает принятые ответы, `decision_deadline_misses` — просроченные запросы, а `decision_slots_busy` — пропущенные моменты отправки из-за занятого потока. `decision_applied_p95_wall_s` измеряет возраст наблюдения при применении команды. `tick_lag_max_wall_s` показывает максимальное опоздание шага симулятора относительно расписания. Ожидание первого ответа и аварийные вмешательства учитываются отдельно от остановок по таймауту.
