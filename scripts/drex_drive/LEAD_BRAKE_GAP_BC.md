# Условный прогноз зазора: закрытая диагностика TRAIN B/C

Эксперимент `corridor-preview-lead-brake-gap-conditional-v1`. Не fresh-v1 и не повтор старого A/B. Когорта неизменна: 23 сцены из 14 поездок архивного TRAIN. **B** регенерирует штатное поле `minimum_lead_gap_if_braking_m` для каждой команды (без лидера — `null`). **C** сохраняет ровно те же значения, только если в текущем причинном радаре выбран лидер и неокруглённая скорость сближения строго положительна. При нуле, расхождении и отсутствии лидера ключ удаляется у всех команд; это три разных причины. Некорректные данные о лидере не считаются отсутствием лидера.

Радар на каждом решении строится из начального измерения/его прогноза и текущего **симулированного** состояния своего плеча. Записанное будущее доступно только скореру. У обоих плеч восемь решений и 40 поз на сцену. Оба используют одну загрузку Drex Max v1 **внутри каждого задания**, argmax и сброс seed `20261124` перед каждым плечом. В каждом текущем состоянии проверяется контрфактическая пара запросов, включая порядок полей, инструкции, команды, длины токенов, отсутствие усечения и влияние ключа на токены. После расхождения состояний запросы из разных плеч не сравниваются как один и тот же снимок.

## До запуска

Нужны отдельные разрешения на Slurm, CPU/Astra по действующему маршруту и выгрузку перечисленных ниже файлов. Никакого автоматического перехода к следующей стадии. Работать на MSU login из корня checkout с уже опубликованным/проверенным кодом. Оператор фиксирует точную ревизию и проверяет отсутствие незапланированных правок; runner записывает HEAD, хеш scoped diff и хеши исполняемых файлов. Не менять checkout до окончания; установка, скачивание весов, получение holdout или замена кешей не входят в протокол.

Нужен готовый `$DREX_RUNTIME_ROOT` (обычно `/scratch/pr0201/drex_runtime`) с `venv/`, `upstream/`, `models/drex-max-v1/` и замороженным `runs/navsim-straight-night-v1/` (наблюдения, corridor export, исторические отчёт и identity/трассы `corridor-preview`; архив только читается). Из `runs/corridor-preview-lead-brake-gap-paired-v1/attempt-002/` обязательны **оригинальные** `comparison.json`, `manifest.json`, `paired-pilot/{runtime,smoke,prediction-receipt}.json`. Сводки идентифицированы по каноническим hashes из проверенных локальных exports; квитанция предсказаний связана с отчётом и с runtime Slurm `301704`. Старый манифест обязан связывать тот же архив, включая наблюдения и хеши кешей. Если оригинальная `paired-pilot/b/f43160170a665c31.json` доступна, она проверяется по старой квитанции и сверяется точная последовательность поз; она никогда не передаётся как вход скорера B/C. Недостающие обязательные файлы, несовпадающие хеши или иной layout — **остановка**, не подставлять сводки от другой попытки.

Нужны существующие SSH-алиас Windows → MSU, одобренный SSH/ControlMaster MSU → Astra и доступ контейнера Astra к установленному TRAIN package/cache, audit tools и NAVSIM repo. Имена/пути на Astra задаются существующими `DREX_ASTRA_{HOST,PORT,CONTAINER,PACKAGE,REPO}`, `DREX_TRANSFER_CONTROL`, `DREX_STRAIGHT_SOURCE`; подтверждает оператор, не вводите секреты в команду/логи. Контрольная проверка Astra требует совпадения `config`, NAVSIM и audit tools, Python и версий пакетов со старой попыткой. Переиспользуется исходный **нереактивный raw** `pdm_score`, 40 × 0,1 с, без human penalty filter; это не официальная формула NAVSIM v1 и не EPDMS. Сверяются кеши, начальные наблюдения, геометрия и raw DrSu на тех же сценах. Записанное будущее не экспортируется в запросы Drex.

## MSU270 login: команды по стадиям

Сначала выберите новый `attempt-NNN`. `$DREX_PARTITION` по умолчанию `batch`. Выполнять блоки **по одному**, только при пройденной предыдущей стадии; `check` показывает ресурсы и очередь, а не резервирует их.

```bash
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime  # замените только на проверенный канонический путь
attempt=attempt-001                                # новая, ещё не существующая директория
runner=scripts/drex_drive/lead_brake_gap.sh
out="$DREX_RUNTIME_ROOT/runs/corridor-preview-lead-brake-gap-conditional-v1/$attempt"
bash "$runner" bc-check "$attempt" && bash "$runner" bc-verify "$attempt"
```

Отдельно, после проверки ресурсов: **GPU smoke одной пары** на `f43160170a665c31`.

```bash
bash "$runner" submit-bc-smoke "$attempt"
```

Оператор видит код `sbatch --wait`; job ID и сообщения — в `$out/brake-gap-bc-smoke-slurm/submit.log`. На compute-узле проверяются Python 3.12, одна видимая GPU с native BF16, fingerprint ПО/upstream/weights из `attempt-002`, затем загружается модель. Запрошено 1 GPU / 4 CPU / 96 GiB; 10 минут smoke, 30 минут pilot, без привязки к узлу и без requeue. Фактические ресурсы и времена узнать только после запуска, например на MSU: `sacct -j JOB_ID --format=JobID,State,ExitCode,Elapsed,ReqTRES,AllocTRES,MaxRSS` (подставьте ID своего задания; храните вывод отдельно, скрипт его не собирает).

После успешного smoke GPU, **на MSU login** открывается существующий Astra bridge и явно запускается **CPU score-smoke**. Эти команды **не вводятся на Astra**: bridge выполняет скорер внутри существующего контейнера Astra; интерактивного шага на Astra нет. `connect` может потребовать установленную авторизацию; не менять маршрут автоматически.

```bash
bash scripts/drex_drive/straight.sh connect &&
bash "$runner" bc-score-smoke "$attempt"
```

Нужны `0` и `smoke-score.json` со статусом `smoke_verified`. Это gate идентичности, не тест превосходства C: оцениваются обе новые траектории, для B проверяются точные NC/TTC, весь сохранённый raw-вектор включая PDM (atol `1e-8`, rtol `1e-7` как в старом скорере), кеш/скорер/DrSu и доступная старая траектория. GPU-квитанция сама по себе не разрешает пилот. Только затем, отдельным запуском:

```bash
bash "$runner" submit-bc-pilot "$attempt"
```

Пилот прежде остальных сцен воспроизводит эту B/C пару (позы, решения, вероятности, запросы и gate-телеметрия; без wall time) и проверяет точное совпадение с отдельно **оценённой** парой. После `0` от Slurm и появления `bc-pilot/prediction-receipt.json`, отдельный финальный CPU-скоринг через тот же мост:

```bash
bash scripts/drex_drive/straight.sh connect &&
bash "$runner" bc-score "$attempt"
```

Оба CPU-шагa сохраняют stdout + stderr, включая доступные Astra logs, в `bc-score-smoke.log` / `bc-score.log` на MSU. Результаты: `0` = `smoke_verified` либо `pass`; `2` = отсутствующий/негодный вход, несовпадение lineage/опоры, сбой транспорта/скоринга или `incomplete`; `3` = **полный** `rejected`, не инфраструктурный сбой. У Slurm/системы возможны собственные ненулевые коды. При незаполненном отчёте сначала смотрите лог и `unscored_tokens`/`first_failed_condition`, не заменяйте вывод и не перезапускайте в той же попытке. Результат полного пилота считается только на 23 точных парах; B сверяется с сохранённым raw-вектором на всех сценах. На совершившейся попытке удерживайте все логи и JSON, даже если результат отрицательный.

Первичное среднее **C−B**, одинаковый вес сцен. Условия `pass`: ни одного падения любой из семи защищённых компонент более `1e-8` на любом токене, NC/TTC C ровно `1` на `f431…` и `cf6c…`, `Δego_progress ≥ +1` п.п., `Δraw PDM > −2` п.п. Метры отдельно. Полный `rejected` содержит все измерения и все причины, победы/поражения/ничьи по PDM, покрытие и причины gate (знаменатели — решения своего плеча), разбивку по поездкам, равный вес поездок, leave-one-drive-out и описательный paired bootstrap целыми поездками (20 000 реплик, seed `20261124`, PDM и progress). Не подтверждение переноса или безопасности.

## Windows PowerShell: выгрузка конкретной попытки

В локальном корне checkout, после завершения текущего шага, чтобы не копировать растущий лог. Родительская локальная директория должна уже существовать, новая попытка выгрузки — ещё нет. `-DryRun` только проверяет аргументы/локальный путь и показывает allowlist; не открывает соединений и не создаёт папок. Подставьте свой разрешённый алиас и путь.

```powershell
$download = '.\scripts\drex_drive\download_lead_brake_gap_bc.ps1'
$params = @{ MsuAlias = 'YOUR_MSU_ALIAS'; MsuRuntimeRoot = '/scratch/pr0201/drex_runtime';
             Attempt = 'attempt-001'; LocalParent = 'D:\approved-results' }
& $download @params -DryRun
# Только после отдельного разрешения на выгрузку:
& $download @params
```

Потребуются `ssh`, современный `scp`/SFTP и установленная аутентификация через алиас. Выгрузка берёт только доступные логи и фиксированные JSON из этой попытки, включая неудачные: для каждой резервации `submit.log`, внешние Slurm stdout/stderr и эксклюзивный комбинированный лог воркера, Astra bridge logs, манифест, runtime, квитанции и парные отчёты. Отсутствующие файлы перечисляются, ошибки копирования дают ненулевой исход и сохраняют частичную папку. Для следующего снимка той же удалённой попытки после ещё одной стадии укажите другой существующий `LocalParent`; старый снимок не затирайте. Логи до создания попытки/отправки, внутренние журналы Astra/Slurm, не попавшие в указанные файлы, и логи недоступного узла этим скриптом не получить. Он не забирает каталоги целиком, любые траектории/промпты, датасеты, кеши, веса, секреты, историю Git или другие попытки. Это обычные файловые предохранители проекта, не защита от произвольного противника.
