# Отдельные последствия и вложенный выбор допуска

Новый запуск `consequence_nested_v2` читает подготовленные `features.npz`,
`labels.npz`, `audit_request.json` из `rollout_audit_drex_probe_v1` на msu270.
Все исходные SHA и старый код проверяются через исходный context.
Старые отчёты и решения не меняются. Новые изображения, scorer или Drex не нужны.

## Постановка

Сохраняем исходные 651 TRAIN-сцену, 32 сессии и 63 альтернативы на сцену.
Пять вариантов признаков одинаковы с v1: DS, DS+text, DS+blank, DS+road,
DS+перемешанные road-оценки. Сравниваем одну одинаковую линейную архитектуру
для всех вариантов; новых подборов архитектуры по внешним результатам нет.

Для непрерывных последствий остаётся ridge: изменение рывка, бокового
ускорения, прогресса, PDM и пикового рывка. Бинарные события теперь обучаются
логистической регрессией с отдельными выходами:

- `raw_harm`: ухудшение NC/DAC/DDC/TLC/TTC/lane/history comfort;
- `geometry_harm`: ухудшение наблюдаемых запасов/контактов/выхода за дорогу
  либо неполное покрытие участников, по прежнему определению v1;
- `progress_violation`: потеря более 1 м или более 5% прогресса DS;
- `comfort_regression`: рост RMS рывка, RMS бокового ускорения или максимума рывка;
- `benefit`: исходное редкое составное полезное изменение из v1.

Прогресс отделён от безопасности. Бинарные головы оптимизируют log loss,
без искусственного изменения доли положительных примеров. Вес одинаков у
сессий, затем у сцен и кандидатов внутри сцены. Нормировки — только TRAIN.
Недоступные запасы не становятся нулями: прежняя маска доступности и её
ограничения сохраняются. Оценки ухудшений относятся к заданным событиям,
а не к вероятности аварии вообще.

## Разделение данных

Четыре внешние группы целых сессий, как в v1. Для каждого внешнего TRAIN:

1. Три внутренние группы сессий дают прогнозы моделей на сессиях, которые
   эти модели не видели при обучении.
2. На этих внутренних прогнозах обучаются отдельные sigmoid-калибраторы.
3. На том же внутреннем наборе подбираются пороги: это **подбор параметров**,
   а не независимая оценка калибровки или правила.
4. Головы переобучаются на всём внешнем TRAIN. Калибраторы и пороги фиксируются.
5. Только теперь прогнозируются внешние отложенные сессии.

Если класса в обучении нет, применяется явный постоянный прогноз. Такие
случаи записываются в `selections`; они не считаются доказательством надёжности
классификатора. Само применение sigmoid не гарантирует хорошую калибровку:
её проверяем по внешним Brier/AP и таблицам predicted/observed частот.
Таблицы частот описательные, строки кандидатов коррелированы.

Допуск требует ограниченных прогнозов raw/geometry/comfort событий,
ограниченного прогноза нарушения бюджета прогресса и прогнозируемой потери
не более 1 м. Среди допущенных альтернатив выбирается максимальная оценка
`benefit`. Пороги перебираются только во внутреннем TRAIN.

Кандидатное правило допускается к внешней проверке, только если внутри TRAIN
не наблюдалось перечисленных ухудшений у выбранных замен и полезные изменения
встретились минимум в трёх сессиях. Далее максимизируется средняя по сессиям
доля полезных замен, при равенстве предпочитается меньше вмешательств.
Это эмпирическое условие, **не статистическая гарантия безопасности**.
Если поддержки нет, сохраняется DS. Ненулевые замены не форсируются.

Сетка допуска включает отключённые ограничения (порог 1.01); их применение
может быть выбрано на TRAIN, если внутренние фактические события проходят
проверку. Поэтому обязательно смотреть реальные ошибки на внешних сессиях.
Это исследовательский replay, не готовый автомобильный контроллер.

Отдельный `ranking_only` всегда выбирает одну из 63 альтернатив по оценке
пользы, без допуска. Это диагностический контроль качества ранжирования,
не правило для применения на автомобиле.

## Запуск

Всё выполняется на msu270 в одной CPU-задаче Slurm: 2 CPU, 16 ГБ, максимум
8 часов. Терминал можно закрыть после `Submitted batch job`. На Astra входить
не надо, GPU не запрашиваются.

Пути репозитория, runtime, исходного запуска и имя результата передаются
batch-скрипту явными аргументами; также задан `sbatch --chdir`. Это необходимо,
поскольку Slurm исполняет свою служебную копию скрипта. Поиск checkout через
расположение этой копии не используется. Тест запуска воспроизводит такой сценарий.

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_CONSEQUENCE_V2_NAME=consequence_nested_v2
bash "$HOME/drivesuprim/scripts/drex/run_consequence_v2.sh" submit
```

Задача сначала выполняет небольшие тесты, затем один полный внешний fold как
технический пилот; после него автоматически остальные. Всего 80 обучений
набора голов: 4 внешних fold × 5 вариантов × (3 внутренних обучения + 1 итоговое).
Время зависит от CPU и сходимости оптимизации. Пилот проверяет исполнение,
не требует получить выигрыш и не определяет выбор гиперпараметров.

```bash
bash "$HOME/drivesuprim/scripts/drex/run_consequence_v2.sh" status
tail -n 30 /scratch/pr0201/drex_runtime/logs/consequence-v2-JOBID.log
```

Если задача прервалась, после её остановки используйте `resume` с тем же именем.
Чекпойнты хранятся по fold и варианту, завершённые обучения повторяться не будут.
Код, входы и окружение привязаны к identity/SHA; перед продолжением их менять нельзя.
Повторная одновременно запущенная задача остановится на файловой блокировке.

Результаты: `/scratch/pr0201/drex_runtime/runs/consequence_nested_v2/`:
`report.json`, `per_scene.csv.gz`, `per_candidate.csv.gz`.
Нужно сравнить `gated` с DS и `ranking_only`, проверить `selections` на постоянные
классы/отсутствие поддержки, оценить AP/Brier и реальные ухудшения вместе с
комфортом и прогрессом. Парные интервалы считаются по целым сессиям.

Все сессии TRAIN уже многократно изучались. Внешний OOF здесь честнее подбора
порогов на тех же прогнозах, но не заменяет независимый свежий holdout.
