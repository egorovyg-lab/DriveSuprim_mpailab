## Сохранённые предсказания и кэши

Два набора предсказаний отличаются в 5852/12146 сценах (48,18%).
На одном v1 scorer/cache получено 86,7300 и 86,7467, разница +0,0167 п.п.
Эта конкретная замена не устраняет расхождение со статьёй.

HumanAgent на полном наборе: 94,5455 PDMS против 94,8.
Основное отличие относится к EP: примерно 86,95 против 87,5.
Это не поправка, которую можно прибавлять к результату модели.

На детерминированной выборке 256 сцен сравнили текущий PDM-Closed
с эталоном из старого exp_v2/metric_cache. Происхождение старого кэша
не установлено. Базовые оценки совпали с прежними CSV.
Замена эталона и отдельно центральной линии не дала видимого эффекта:

| Model | 84.7781 | 84.7781 | 84.7781 |

Это не проверка эквивалентности кэшей на всём наборе. Средние по выборке
не являются воспроизведением таблицы статьи.

## Загрузка весов и словарь

872 ожидаемых ключа; 0 пропущенных, 0 лишних, 0 пропущенных ключей teacher.
После загрузки значения совпадают с соответствующими значениями checkpoint.
Проверяется повторная загрузка сейчас, а не дамп памяти прошлого процесса.

Student vocabulary точно совпадает с файлом: 8192 x 40 x 3.
Teacher отличается максимум на 0,000709533722 м по позиции,
в среднем на 0,000025215667 м, максимум на 0,000026464462 рад по направлению.
Все траектории отличаются по позиции менее чем на 1 мм.
У 64/64 проверенных траекторий ближайшая траектория student имеет тот же индекс.
Это проверка соответствия индексов на выборке, а не полное доказательство.

EMA в опубликованном коде обновляет все параметры, включая vocabulary
с requires_grad=False. Отличия согласуются с численным дрейфом EMA,
но их причина и влияние на дискретный выбор не доказаны.
Checkpoint и словарь не подменялись для повышения результата.

## Что пока не подтверждено

1. README документирует опубликованные чекпойнты через EPDMS v2.
   Не подтверждено, что те же веса использованы для 89,9 PDMS v1.
2. В checkpoint есть history_comfort, отдельной головы C нет.

   из таблицы 8; фактический комфорт считается функцией v1.
   Это соответствие не подтверждено авторами.
3. Точный NAVSIM commit, команда и кэш для таблицы 2 не указаны явно
   в проверенной публичной инструкции.

   В проверенном верхнем каталоге Hugging Face отдельного выпуска v1 не найдено.
   Это не утверждение о непубличных артефактах.

## Проверка протоколов: полученные результаты

Полный контролируемый тест TTC на 12146 сценах, предоставленный пользователем:
базовые метрики воспроизведены по сценам; независимая проверка короткого TTC
по первому нарушению полного TTC прошла. Кэш, состояния после симулятора,
reference, NC, DAC, EP и комфорт не менялись.

| Вариант | TTC, % | PDMS, % |
|---|---:|---:|
| v1.1, ego до 4,0 с | 90.8859 | 86.7300 |
| Только TTC: ego до 3,1 с | 96.5009 | 88.9221 |
| Статья, таблица 2 | 93.6 | 89.9 |

Изолированная разница TTC: +2,1921 п.п. PDMS.
TTC изменился в 682 сценах, положительный прирост PDMS — в 639.
Это примерно 69% исходной численной разницы со статьёй, но не доказательство
авторского протокола. TTC короткого варианта выше опубликованного 93,6%.
Остаток до 89,9 — примерно 0,9779 п.п.; окна не подбирались по целевому числу.

Построчный пересчёт старой формулы на фактическом CSV v2:
NC*DAC*(5*EP+5*TTC+2*HC)/12 = 88,8797084723%.
Разница с сохранённым v1: +2,1496799917 п.п.; со статьёй: -1,0202915277 п.п.
Таким образом, одной замены агрегации недостаточно для воспроизведения 89,9.
Численная близость 88,8797 и 88,9221 не означает совпадения протоколов.
