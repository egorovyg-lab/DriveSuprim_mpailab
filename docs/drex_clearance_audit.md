# Проверка запаса до границ и участников движения

Аудит измеряет, как исполнение меняет геометрический запас у тех же шести
пар: 12 кандидатов, по два пути (исходный и после симулятора).
Исходные scorer, контроллер и их настройки сохраняются.

## Запуск с msu270

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_CLEARANCE_SOURCE=rollout_audit_pair6_v2
export DREX_CLEARANCE_NAME=rollout_audit_clearance_pair6_v1

bash scripts/drex/run_clearance_audit.sh connect &&
bash scripts/drex/run_clearance_audit.sh start
```

После `start` можно выйти с сервера: мост работает через `nohup`.
`connect` использует тот же SSH ControlMaster, пароль при необходимости
вводится в терминале и не сохраняется. Новый checkout Astra не требуется:
инструменты доставляются в отдельный каталог `drex_rollout_audit`.

```bash
bash scripts/drex/run_clearance_audit.sh status
```

Статус показывает компактную таблицу и точный путь артефактов. Полный
`report.json`, 24 JSON с покадровыми измерениями и 24 CSV возвращаются на
msu270 с SHA-проверкой. Старый аудит остаётся сохранённым.

Вычисления выполняются на CPU Astra в контейнере `egorov_drivesuprim`.
GPU, очередь Slurm, новые изображения, новая симуляция и вызовы scorer/Drex
не требуются. Используются готовые states из успешного аудита 12/12,
исходные SHA-bound metric caches и текущие установленные SDK-библиотеки.

## Что измеряется

Для каждого отсчёта 0,1 с, включая начальный:

- **cornerDAC:** исходная проверка четырёх углов, воспроизведённая по тем же
  полигонам. Маски должны совпасть с прошлым аудитом побитно.
- **fullBody:** весь прямоугольник автомобиля покрыт объединённой допустимой
  областью. Проверяются также рёбра и внутренность — четырёх углов недостаточно
  при отверстиях и вогнутых границах.
- **roadMin:** минимальное расстояние полного габарита до границы объединённой
  области. Внутренние швы между дорожными полигонами удаляются объединением.
  Если в любой момент часть машины снаружи, значение `null`/`NA`.
- **cornerMin:** отдельно подписанное расстояние ближайшего угла. Внутри —
  положительное, снаружи — отрицательное, на границе — ноль. Оно не подменяет
  проверку всего прямоугольника.
- **outside:** максимальная площадь части габарита вне области, м².
- **LK/counter:** исходный счётчик удержания полосы относительно centerline
  scorer, включая пропуск перекрёстков без сброса. Учитывается лимит из frozen
  config. Счётчик не переводится в «непрерывную длительность» при пропусках.
- **actorMin/contact:** минимальное расстояние полного габарита до записанных
  объектов в соответствующий момент и первое геометрическое пересечение.
  Используется исходная non-reactive traffic policy с тем же удалением
  объектов, уже пересекающих ego в начале. Отсутствие объектов обозначается
  `null`, а не бесконечным/искусственно большим запасом.

Геометрическое пересечение с объектом не определяет виновность и не заменяет
NC/TTC. Данные о будущем traffic используются только в этом диагностическом
аудите. Они не передаются Drex и не являются готовым доступным онлайн-входом.

Границы допустимой области карты не отождествляются со сплошной разметкой на
фотографии. Удержание полосы считается отдельно от запаса до границы дороги.
Ошибки калибровки и окклюзии фотографий на численные расстояния карты не влияют.

## Таблица допустимости

Для исполненных кандидатов фиксированы буферы **0 / 0,1 / 0,25 / 0,5 м**.
В список попадает кандидат, у которого на всех сохранённых отсчётах:

1. проходит исходный cornerDAC и покрыт весь габарит;
2. запас до границы области не меньше буфера;
3. проходит исходное удержание полосы;
4. нет геометрических контактов с записанными объектами, а расстояние до
   них не меньше буфера, когда объекты есть.

`[]` означает, что ни один кандидат пары не прошёл эти условия; `[0,1]` — оба.
Числа **не подбираются по результатам**, правило не объявляется безопасной
политикой и автоматически не внедряется в выбор Drex. Оно не учитывает все
метрики PDM. Сравнение на шести заранее выбранных случаях описательное.
Проверки на сетке 0,1 с не гарантируют отсутствия нарушения между отсчётами.

При изменении исходного SHA, габаритов, corner masks или lane counters аудит
останавливается. Автоматическое исправление полигонов не используется.
Ошибка сохраняется; для изменённых инструментов требуется новое имя результата.

Локальные тесты: `python -m unittest discover -s scripts/drex -p test_clearance.py -v`.
Часть геометрических тестов требует NumPy/Shapely; при их отсутствии unittest
явно помечает их как пропущенные. Runtime Astra уже содержит эти зависимости
для исходного scorer. На msu270 мост и просмотр результата используют только
стандартную библиотеку Python.
