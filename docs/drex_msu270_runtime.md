# Подготовка Drex Max на msu270

Проверено через Slurm: cn29.sc.test, A100-SXM4-80GB, Python 3.12.3,
драйвер 580.178.04. Код в ~/drivesuprim, ветка codex/drex-max от c6279ad.
Скрипты готовят окружение и выполняют synthetic text/image smoke полной модели.

После commit/push новых файлов в codex/drex-max, на msu270:

```bash
cd ~/drivesuprim
git pull --ff-only
bash scripts/drex/run_runtime.sh tests
bash scripts/drex/run_runtime.sh prepare
```

На login node Python 3.10.12, на вычислительном узле Python 3.12.3.
Поэтому wrapper не проверяет и не запускает venv на login node, даже если
venv/bin/python там выглядит нерабочей ссылкой. Tests работают на Python 3.10.
Prepare сам выделяет через Slurm одну GPU, 4 CPU, 16 GB RAM, до 30 минут.
Внутри одного job step последовательно выполняются setup, gpu-check, model-plan,
без вложенных srun. Ошибка любого этапа останавливает цепочку. Веса не скачиваются.
Флаг --inside предназначен только для wrapper и требует реального job step.

Setup на вычислительном узле создаёт отдельный ~/drex_runtime/venv с Python >=3.12,
клонирует официальный runtime на фиксированный commit и устанавливает зависимости.
Системное окружение и DriveSuprim не меняются. Пакеты могут занимать несколько GB.
Нужен сетевой доступ к GitHub/PyPI с вычислительного узла. Если его нет или модуль
venv/ensurepip отсутствует, пришли ошибку: подготовим установку через Enroot или
доступный кластерный mirror. Sudo автоматически не используется. Существующий
venv старой версии не удаляется: для другого протокола выбрать новый runtime root.

После успешной установки сохраняется pip freeze; повтор setup не обновляет
пакеты. Check сравнивает окружение с этим снимком. Это запись первого разрешения
официальных зависимостей, не заранее подтверждённая на A100 сборка. Отдельные
setup, check и gpu-check также отправляются через Slurm. Check/gpu-check
запрашивают одну GPU, 8 GB RAM, 2 CPU, до 5 минут; проверяют импорты и BF16
(вычисления BF16 выполняет именно gpu-check).
Ждёт выделения ресурсов в обычной очереди Slurm, без --immediate. Лимит времени
задачи считается после запуска, не ограничивает ожидание в очереди. Чужие задачи
не отменяются, настройки очереди не меняются. Пока srun ждёт, терминал может
долго не печатать вывод; статус можно посмотреть через squeue -u "$USER" в другом
терминале. Ctrl+C прерывает собственный вызов srun; затем проверить squeue.
Полную совместимость vision/DeltaNet
подтвердит отдельный запуск с весами. Не запускать полный инференс на login node.

После успешного setup в setup_node.txt сохраняется SLURMD_NODENAME. Отдельные
model-plan и download отправляются как CPU-задачи на этот узел, --gres=none:
у них тот же Python/ОС, и они не занимают GPU ради сети. Внутри prepare
model-plan использует уже выделенную задачу. При недоступности сохранённого узла
Slurm сообщает ошибку/истечение ожидания; повтор prepare может выбрать другой
совместимый GPU-узел. Имя узла берётся из Slurm, не угадывается по hostname.

Model-plan получает только metadata HF, фиксирует полный revision, размеры
и список нужных файлов. Он не скачивает веса. Перед загрузкой около 52 GB:

```bash
df -h ~/drex_runtime
quota -s
```

Если quota недоступна, ориентироваться на правила хранения кластера, не только
на общий свободный диск. Домашний каталог/venv должны быть доступны GPU-узлу.
Для иного хранилища до setup задать DREX_RUNTIME_ROOT=/доступный/путь, одинаково
для всех стадий. Учитывать, что venv и данные должны быть на общей файловой системе.

Загрузка — отдельная явная команда, только после успешного gpu-check:

```bash
bash scripts/drex/run_runtime.sh download
```

Используется зафиксированный HF revision; загрузка возобновляется. Проверяются
размеры локальных файлов. Это ещё не полная checksum verification, не принятие
модели и не результат вождения. JSON отчёты и модель находятся вне git checkout.
NAVSIM данные/labels, старые эксперименты и четыре fresh holdout не читаются.
Download получает до 45 минут, 8 GB RAM, 2 CPU и не запрашивает GPU.

DREX_PARTITION по умолчанию batch. Значения --account/--qos, если они нужны,
уточняются по настройкам кластера. BF16-проверка требует GPU с >=70 GiB VRAM:
случайно выделенная более маленькая GPU вызывает понятную остановку.

## Проверка скачанной модели в фоне

После успешной загрузки обновить код и подать задание с login node:

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
bash scripts/drex/run_runtime.sh tests && bash scripts/drex/run_runtime.sh submit-smoke
```

После Submitted batch job <номер> можно закрыть SSH/VS Code. Один GPU, 4 CPU,
96 GB RAM, максимум 20 минут выполнения; обычная очередь, без --immediate.
Sbatch запрашивает ресурсы один раз, внутренний srun запускает только job step.
Лог: /scratch/pr0201/drex_runtime/logs/smoke-<номер>.log. Для foreground запуска
доступна команда smoke, но она зависит от текущего SSH-соединения.

Проверки: прежний environment lock; наличие и размеры всех файлов модели;
non-causal full attention; официальный loader с BF16 и batch=1; текстовый вопрос;
два одноцветных изображения с одинаковым вопросом; повтор текста. Проверяется
наличие pixel_values в подготовленном визуальном запросе, корректность вероятностей
и ожидаемые ответы BLUE/red/blue/BLUE. Изменение вероятностей в повторе отдельно
логируется; нулевая разница не является обязательным критерием. Локальная
проверка 52 GB весов по полным checksums этим этапом не выполняется.

Тест не запускает установку/скачивание весов и не читает NAVSIM. При исключении
сохраняет traceback и этап, при ошибочном ответе — semantic_smoke_failed. Успех —
status=complete и passed=true. Это проверка исполнения, не вождения или safety.
Первый запрос может включать компиляцию kernels, поэтому времена холодного
и повторного запросов показываются отдельно. Исходный runtime не модифицируется.

Отчёт: /scratch/pr0201/drex_runtime/runs/smoke-<UTC>/report.json. В конце лога
показывается полный отчёт с report_path. Начатая работа сохраняет status=running;
если Slurm завершит процесс сигналом/таймаутом, проверять sacct и лог, не считать
этот файл успешным. Готовые отчёты не перезаписываются; повтор — новый запуск.

```bash
squeue -u "$USER"
tail -n 100 /scratch/pr0201/drex_runtime/logs/smoke-НОМЕР.log
sacct -j НОМЕР --format=JobID,State,ExitCode
```
