# Проверка длительности обучения и ёмкости данных

Текущее обучение — небольшой селектор поверх замороженного DriveSuprim,
399 сцен / 22 поездки. Это не полное переобучение камеры/backbone DriveSuprim.
Больше эпох может помочь при недообучении, но также усилить переобучение.
Последние loss на 120 эпохах сами по себе не позволяют выбрать между этими
объяснениями: нужны результаты на исключённых из обучения поездках.

Новые файлы не меняют замороженные v2 model/trainer/collector/bundle, поэтому
существующий результат на 120 эпохах используется как контроль.

## Запуск внутри контейнера

После commit/push/pull:

```bash
cd /workspace/DriveSuprim
bash scripts/drivesuprim/evaluation/run_selector_scale.sh check
bash scripts/drivesuprim/evaluation/run_selector_scale.sh plan
```

Оценить возможность увеличения данных:

```bash
bash scripts/drivesuprim/evaluation/run_selector_scale.sh capacity \
  > /workspace/exp_v2/selector_capacity_v1.json
cat /workspace/exp_v2/selector_capacity_v1.json
```

Это чтение metadata и проверка наличия архивов. Изображения, features и labels
не извлекаются; даже JSON manifests не скачиваются. Отчёт показывает запас в
скачанных архивах и отдельные варианты дополнительных архивов со стоимостью.
Их counts пересекаются и не должны суммироваться. Size match — оценка для
планирования, перед извлечением нужен SHA256. Уже извлечённые изображения без
сохранённого архива не учитываются. Существующие 399 timestamp служат anchors;
новые сцены отстоят от них и друг от друга минимум на 10 секунд. Лимит — 128
сцен на сессию; новая сессия должна иметь минимум 16 сцен. Защищённые сессии,
включая четыре fresh holdout, исключаются целиком.

Это оценка ёмкости, а не готовая большая обучающая выборка. После отчёта можно
зафиксировать новый manifest, извлечь выбранные train images, собрать features
и top16 labels и построить новый bundle. Для новых архивов объём согласуется
по конкретному плану; прежние 30 ГБ уже использованы и не являются разрешением
на повторную загрузку ещё 30 ГБ. Дополнительные сцены прежних поездок увеличивают
плотность, новые поездки увеличивают разнообразие; оба числа выводятся отдельно.

Более длительное обучение на текущих 399 сценах:

```bash
nohup bash scripts/drivesuprim/evaluation/run_selector_scale.sh long-fit \
  > /workspace/exp_v2/selector_duration_v1.log 2>&1 &
tail -n 50 /workspace/exp_v2/selector_duration_v1.log
```

Два последовательных CPU запуска: 360 и 1000 эпох, обе семьи моделей,
такие же leave-one-session-out folds, seed, optimizer и loss. Относительно
120 эпох это 3x и 8.33x шагов на fold; суммарно около 11.33x шагов прежнего
обучения. Это не точный прогноз времени. GPU для обучения селектора не нужен.
Экспорт признаков для будущей расширенной выборки потребует GPU.

Выходы — `experiments/selector_duration_v1/epochs360` и `epochs1000` внутри
`/workspace/exp_v2/drivemem_memory`. Повтор команды возобновляет завершённые
folds/модели. Не запускать два процесса в один каталог. На этом этапе старые
development-когорты заново не оцениваются и fresh holdout не открывается.

После завершения сравнение также печатается в лог. Отдельная команда:

```bash
bash scripts/drivesuprim/evaluation/run_selector_scale.sh compare
```

Сравниваются loss внутри одной семьи, OOF raw/gated gain, component harm,
снижения PDM и количество вмешательств. Перед сравнением проверяются hashes
артефактов и идентичность всех условий, кроме числа эпох. Если train loss
падает, а OOF качество ухудшается, это довод против дальнейшего увеличения
эпох при этих условиях. Если OOF улучшается — основание проверить выбранную
длительность далее, но не доказательство независимого эффекта. Выбор эпох и
gate по OOF является настройкой. Confidence benefit не калиброван, local PDM
не равен EPDMS. Параллельное изменение и объёма, и длительности затруднит
определение причины эффекта: сначала сравниваем длительности на одном bundle,
потом размеры данных при зафиксированных условиях.

Пути задаются `SELECTOR_SCALE_ROOT`, `SELECTOR_SCALE_REFERENCE`,
`SELECTOR_DATA_ROOT`, `SELECTOR_DATA_ARCHIVES`, `SELECTOR_BUNDLE_ROOT`.
Число потоков для обучения — `SELECTOR_V2_THREADS`; оно должно совпадать с
контрольным экспериментом, чтобы сравнение оставалось строгим.
