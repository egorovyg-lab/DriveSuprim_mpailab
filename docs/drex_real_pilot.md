# Drex на реальных кандидатах DriveSuprim: первый офлайн-пилот

Пакет уже перенесён на msu270:
`/scratch/pr0201/drex_runtime/data/navsim_train_v1/package`.
Содержит 651 train-сцену, 32 сессии, камеры, словарь, признаки и raw/filtered
top16 labels. Старые функции `load_bundle()` с абсолютными путями Astra не
используются. Старый синтетический запуск и его файлы остаются без изменений.

## Фиксированный протокол

Выбираются 64 сцены: по две из каждой сессии, сортировкой SHA256 от seed и
token, без PDM-меток. Сессии также перемешиваются фиксированным хешем;
первые четыре сцены короткого пилота принадлежат разным сессиям. Неподходящие
или повреждённые сцены не заменяются: команда останавливается для разбора.

Пул — прежние top16 по teacher selection score с исходным baseline внутри.
Словарь проверяется на `[N,40,3]`: абсолютные ego-local позы через 0.1 s до
4 s, x вперёд, y влево, heading против часовой стрелки. Это соответствует
`DriveSuprimConfig.trajectory_sampling`, а не стандартному NAVSIM sampling
с шагом 0.5 s. Перед inference читаются только candidate IDs, teacher scores
для фиксации пула, baseline index и ego status. Из них модели передаются
только текущие скорость/ускорение и визуализации путей. Teacher scores,
baseline identity, metric heads, labels, tokens и названия сессий в запрос не
включаются. Команда маршрута не расшифрована и не подаётся — это ограничение
интерфейса относительно исходного DriveSuprim.

Запрос содержит два изображения:

1. Фотографии front-left/front/front-right из двух последних доступных кадров.
   Предыдущий кадр сверху, текущий снизу. Виды подписаны, сохранены пропорции;
   это не калиброванный панорамный снимок. Будущие кадры не используются.
2. 16 отдельных схем кандидатов с общей метрической шкалой, отметками времени
   1/2/3/4 секунды и координатами конечной точки на схеме. Схема не содержит
   карты, объектов или разметки дороги. Граница панели не является обочиной.

Калибровки камер остаются в пакете. Проекции траекторий поверх фотографий в
этом протоколе нет: не подменяем проверку координат визуально правдоподобным
наложением. Preflight проверяет формы массивов, принадлежность token/session,
хронологию четырёх кадров истории, размеры/декодируемость изображений и SHA256
пакета. Четыре пары preview сохраняются для проверки интерфейса человеком.

Каждая сцена даёт четыре запроса:

- `camera/canonical`: фиксированный случайный порядок кандидатов;
- `camera/reversed`: обратный порядок тех же кандидатов и панелей;
- `camera/permuted`: фиксированный циклический сдвиг на пять позиций;
- `blank/canonical`: те же ego motion, текст и схемы, фотографии заменены белыми
  полями; подписи камер сохранены. Контроль проверяет влияние дорожных фотографий.

Основной метод **`drex_mean3`**: сначала сопоставить вероятности исходным
кандидатам, затем усреднить три camera-распределения и выбрать максимум.
Порядок, формулировка и метод зафиксированы до оценки; не выбирать удачную
перестановку по PDM. При точном равенстве максимумов baseline сохраняется,
если входит в равные максимумы; иначе используется первый в исходном top16.
Остальные методы: baseline, один camera-запрос, blank-контроль, фиксированный
случайный кандидат. Oracle top16 вычисляется только после фиксации решений и
отмечается как недостижимый при inference ориентир с доступом к исходам.

## Обновление и CPU-проверки

В терминале **msu270**, из каталога репозитория:

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime

bash scripts/drex/run_runtime.sh tests
bash scripts/drex/run_runtime.sh real-check
bash scripts/drex/run_runtime.sh real-plan
```

`real-check` запускает девять новых тестов в compute-node venv без GPU.
Локальная команда `tests` может пропустить их, если в login Python нет
NumPy/Pillow; `real-check` требует эти библиотеки. `real-plan` тоже CPU-only
на сохранённом setup-узле: проверяет пакет, фиксирует выборку/код/параметры,
сохраняет plan и preview. Никаких scorer calls или чтения outcome arrays.
Команды стоят в обычной очереди. Не запускайте несколько команд пилота сразу.

Выход: `$DREX_RUNTIME_ROOT/runs/real_train64_v1/`.
Проверить `plan.json`, `selection.json`, `preview-*-1.png` (камеры),
`preview-*-2.png` (кандидаты). В plan ожидается 64 сцены / 32 сессии /
256 запросов / `outcomes_read: false`.

## Короткий запуск на A100

```bash
bash scripts/drex/run_runtime.sh submit-real-pilot
```

Одна GPU, 4 CPU, 96G RAM, до 30 минут. 16 новых запросов, обычно четыре сцены;
при повторном вызове — следующие 16 ещё не готовых запросов. Это проверка
inference, изображения/контекст/VRAM; PDM-метки ещё не читаются.

```bash
tail -n 50 "$DREX_RUNTIME_ROOT/logs/real-pilot-NNN.log"
cat "$DREX_RUNTIME_ROOT/runs/real_train64_v1/inference_status.json"
```

После первого запуска ожидается `status: partial`, `completed_requests: 16`,
`expected_requests: 256`, `outcomes_read: false`. Частичный статус здесь штатный.
Для двух изображений требуется `image_grid_thw` с двумя элементами, max context
8192, batch=1, BF16. Веса не скачиваются и не дообучаются.

## Полная серия

Если preview и короткий запуск корректны:

```bash
bash scripts/drex/run_runtime.sh submit-real
```

Одна GPU, 4 CPU, 96G RAM, до четырёх часов; мягкая остановка inference через
три часа между запросами. После `Submitted batch job NNN` можно закрыть SSH.
Нет эксклюзивного захвата узла или вмешательства в чужие задания.

Каждый запрос атомарно сохраняется в `results/`. При возобновлении проверяются
SHA256, точные пиксели/текст и сопоставление кандидатов; готовые ответы не
вычисляются заново. Техническая ошибка сохраняется и не повторяется молча.
Сначала изучить `failure.json` и файл результата; при изменении протокола
нужно новое имя `DREX_REAL_NAME`, старые результаты сохраняются.

Когда готовы **все 256 запросов**, сохраняются `decisions.json` и
`decision_commit.json`, связывающий всю выборку, вероятности и решения.
Только после этого отдельная функция читает `label_indices` и `label_raw`
из NPZ. До фиксации всей выборки оценка запрещена. Отсутствие итогового
`report.json` у короткого/частичного запуска не означает ошибку.

## Результат

```bash
sacct -j NNN --format=JobID,State,ExitCode
cat "$DREX_RUNTIME_ROOT/runs/real_train64_v1/report.json"
```

`report.json`, `per_scene.csv`, `per_scene.json` содержат raw local PDM,
парный gain относительно сохранённого baseline, ухудшения PDM отдельно от
ухудшений NC/DAC/DDC/TLC/TTC, вмешательства и результат по каждой сессии.
Для среднего gain приводится session-cluster bootstrap CI. Вероятности Drex
не интерпретируются как калиброванная оценка риска.

Это **исследовательский результат на ранее размеченных train-сценах**, уже
использовавшихся в прошлых экспериментах. Выборка архивная и нерепрезентативная;
интервал не устраняет это смещение. Он не доказывает качество на независимом
benchmark, full EPDMS или реальном автомобиле. Fresh holdout не открыт.

Повторный отчёт без загрузки Drex на GPU:

```bash
bash scripts/drex/run_runtime.sh real-report
```

Команда проверяет все commitments и запрещена до завершения всей серии.
Исходный PDM не пересчитывается по компонентам, NAVSIM/scorer не требуется.
