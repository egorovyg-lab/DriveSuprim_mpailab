## 1. Независимая задача на A100

384 фиксированные синтетические схемы, по 96 с 2/8/16/32 вариантами.
Четыре равных семейства: свободная дорога, узкая дорога, препятствия,
сочетание ограничений. На каждой схеме семь запросов:

1. Численные координаты без изображения.
2. Координаты с изображением.
3. Изображение без координат препятствий/траекторий.
4. То же изображение с обратным порядком вариантов и панелей.
5. Другая фиксированная перестановка.
6. Точный повтор третьего запроса.
7. Белое изображение вместо схемы, прочий текст как в третьем запросе.

Итого **2688 запросов**, BF16, batch=1. Максимум 2 Mpixels и 8192 токена.
Во всех режимах указаны прогрессы вариантов. Геометрический код проверяет
непрерывное движение прямоугольного следа фиксированной ориентации,
выбирает допустимые варианты с максимальным прогрессом и принимает равные
оптимумы. Это искусственная задача чтения кандидатного интерфейса:
кинематика, реальные камеры, динамика участников и NAVSIM здесь отсутствуют.
Особенно близкие касания могут быть неоднозначны после растеризации.

План и четыре изображения-примера, **без GPU**:

```bash
bash scripts/drex/run_runtime.sh night-plan
```

Необязательный короткий пилот — 28 новых запросов, включая 32 варианта:

```bash
bash scripts/drex/run_runtime.sh submit-night-pilot
```

Для ночи достаточно сразу полного запуска: он начинает с тех же первых
четырёх схем и останавливается при технической ошибке. Если пилот уже прошёл,
он продолжит после сохранённых результатов. Не запускайте пилот и полную
серию одновременно.

```bash
bash scripts/drex/run_runtime.sh submit-night
```

После `Submitted batch job NNN` можно закрыть SSH/VS Code. Выделяется **одна
GPU, 4 CPU, 96G RAM, до 8 часов** через обычную очередь Slurm. Нет
`--immediate`, эксклюзивного захвата узла или вмешательства в чужие задания.
Мягкая остановка сбора через 6 часов, проверка лимита между запросами.
Завершится раньше, если все запросы готовы; повторов ради заполнения ночи нет.

```bash
squeue -u "$USER"
tail -n 60 "$DREX_RUNTIME_ROOT/logs/night-NNN.log"
cat "$DREX_RUNTIME_ROOT/runs/synthetic_night_v1/report.json"
sacct -j NNN --format=JobID,State,ExitCode
```

Каждый ответ хранится отдельно, запись атомарная. Повтор `submit-night`
пропускает готовые запросы после проверки входов/пикселей/контрольных сумм.
Смена кода, модели или окружения требует нового `DREX_NIGHT_NAME`.
Записанная техническая ошибка не перезапускается молча. Сначала изучить
`failure.json` и соответствующий файл в `results/`; ослаблять проверки или
подбирать удачный повтор нельзя. При необходимости новый протокол получает
новое имя, старые результаты сохраняются.

Отчёт разделяет условия, число кандидатов и семейства. Содержит число
недопустимых/оптимальных выборов, остановок, долю достигнутого допустимого
прогресса, изменения выбора при перестановке и при точном повторе. Изменение
между равноценными траекториями отдельно от изменения безопасности/прогресса.
Задержки p50/p95 исключают первый вызов каждой загрузки; это разные размеры
входов, а не контролируемый скоростной бенчмарк. Общие агрегаты по всем семи
условиям не являются оценкой качества вождения.

## 2. Одновременно — данные Astra → msu270, без GPU

Пакет содержит **только текущий train bundle** (ожидается 651 сцена,
32 сессии), словарь траекторий, признаки/разметку в исходных NPZ,
изображения восьми камер на четырёх кадрах истории и калибровки текущих камер.
Исходные метаданные provenance сохраняются. Сохранённые protected/holdout
сессии запрещены. Будущие кадры, полные исходные pickle-логи, карты, веса,
metric_cache и архивы `.downloads` не копируются. Разметка остаётся отдельными
полями, её нельзя подавать модели как вход.

Адрес: `egorov@93.180.62.99:27434`, контейнер `egorov_drivesuprim`.
Сборщик загружается в `/workspace/exp_v2/drex_transfer_tool.py`; checkout
репозитория Astra менять не нужно. Используются установленные доверенные
OpenScene pickle-метаданные. GPU и обучение на Astra не запускаются.

Один раз авторизоваться **в терминале msu270**:

```bash
bash scripts/drex/run_transfer.sh connect
```

SSH спросит пароль аккаунта Astra или доступную фразу ключа. Не вставляйте
его в команды/чат. Скрипт не сохраняет пароль: отдельный SSH ControlMaster
держит авторизованное соединение до 12 часов. Ключи и `authorized_keys`
не меняются. Сокет: `~/.ssh/drex-astra-transfer.sock`.

Затем запустить фонового работника:

```bash
bash scripts/drex/run_transfer.sh start
bash scripts/drex/run_transfer.sh status
```

Можно закрыть клиентское SSH-соединение. Это отдельный `nohup`-процесс на
login-узле для сетевого копирования, а не GPU-задача. Если политика кластера
завершает все пользовательские процессы при logout, соединение/копирование
прервутся, но файлы останутся пригодными для возобновления. После нового
входа повторить `connect`, `start`. Поддерживается один работник на runtime.

Сначала собирается train-only snapshot в контейнере:
`/workspace/exp_v2/drex_transfer/navsim_train_v1`, затем несжатый
`navsim_train_v1.tar` рядом с ним. JPEG повторно не сжимаются. Нужен запас
места примерно на две копии полезных файлов на Astra и на msu270.
Точный объём определяется сборщиком; предел передачи по умолчанию 30 GB.
Это перенос имеющихся данных, без новых скачиваний OpenScene.

На msu270 результат:

```text
/scratch/pr0201/drex_runtime/data/navsim_train_v1/
  transfer_report.json
  training.tar
  package/
    package_manifest.json
    scene_inputs.json
    bundle/             # признаки, кандидаты, исходные раздельные метки
    images/             # только история выбранных train-сцен
```

После обрыва сохраняется `.part`. Перед продолжением SHA256 его префикса
сравнивается с Astra; после передачи проверяется весь архив, при распаковке —
каждый файл. Неизвестные пути, ссылки, дубли и выход за каталог запрещены.
Повреждённые файлы сохраняются для разбора, не считаются успешной передачей.

```bash
bash scripts/drex/run_transfer.sh status
bash scripts/drex/run_transfer.sh verify
```

`transfer_report.json` со статусом `verified` означает готовый перенос.
Старый `load_bundle()` на другом сервере не вызывается: он привязан к абсолютным
путям Astra. Переносимый manifest проверяет копии самостоятельно. Для будущего
реального пилота Drex будет отдельный адаптер с разделением наблюдений и меток.

Локальные тесты покрывают геометрию, равные оптимумы, перестановки, точный
повтор, разрыв/возобновление, повреждения файлов, train-only membership,
безопасную распаковку и маршрутизацию Slurm. Реальная A100/сеть проверяются
запусками на сервере, локально они не имитируют качество модели.
