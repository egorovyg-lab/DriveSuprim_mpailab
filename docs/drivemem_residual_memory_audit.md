# Разбор ошибок памяти на завершённом top64 эксперименте

Аудит только читает исходный `residual_memory_top64_v1`. В отдельный каталог
`residual_memory_top64_v1_diagnostic_v1` записывается диагностический отчёт.
CPU, NumPy/Pandas; без нового обучения, NN inference, scorer, Drex и holdout.
Замороженные source-файлы эксперимента не изменены, identities сохраняются.

После `git pull --ff-only origin main`, на Astra:

```bash
docker exec -w /workspace/DriveSuprim egorov_drivesuprim \
  python -m unittest discover -s scripts/drivesuprim/evaluation \
  -p 'test_audit_drivemem_residual_memory.py' -v

docker exec -w /workspace/DriveSuprim egorov_drivesuprim \
  python -u scripts/drivesuprim/evaluation/audit_drivemem_residual_memory.py \
  /workspace/exp_v2/drivemem_memory/experiments/residual_memory_top64_v1
```

Ожидается воспроизведение исходных чисел: семь новых safety-degraded сцен,
пять устранённых прежних, восемь сцен с safety хуже выбранной C1 траектории,
средняя разница C2−C1 около −0,5041 п.п. Аудит проверяет совпадение с исходным
summary и hashes всех входов/решений. При расхождении он останавливается.

В `summary.json` — все смены C1→C2, их польза/потери и классификация ошибки
переноса. `all_scenes.csv` и `per_session.csv` сохраняют полный состав,
не только выбранные плохие примеры. В `cases/*.json` попадают все новые
safety-ошибки, все восемь safety-ухудшений относительно C1, десять крупнейших
потерь и пять крупнейших улучшений (если они есть). Это разбор после оценки,
а не новая независимая выборка или правило отбора траекторий.

Для каждого выбранного действия C1 и C2 показываются:

- настоящие raw-компоненты и оба сохранённых прогноза gain;
- требуемый остаток `actual gain − C1 prediction`;
- поправка памяти, взвешенное среднее остатков до усадки и её множитель;
- каждый донор, его сессия, действие, actual gain, исторический OOF prediction,
  остаток и точный вклад в поправку;
- расстояние и четыре составляющие: context, DS heads, geometry, decoder;
- исходный cross-fit, подтверждение исключения сессий и воспроизведение
  сохранённых расстояний/весов/поправок из неизменённых данных.

Для смены C1-действия A на C2-действие B сравниваются:

`required gap = [true gain(B) − f(B)] − [true gain(A) − f(A)]`

`memory gap = correction(B) − correction(A)`.

`wrong_direction` означает противоположный знак поправки; `same_direction_overshoot`
— правильный знак, но такая величина, что ошибка разности не уменьшается;
`gap_error_reduced` — ошибка разности уменьшилась. Последнее само по себе
не означает правильного выбора: величины может не хватить для исправления
ошибочного рейтинга C1. Эти категории не доказывают причинную роль конкретной
детали дороги. Семантическое несоответствие ситуаций потребует отдельного
разбора наблюдений: близость embeddings этого не устанавливает.

Query outcomes используются только в диагностике. Никакой порог или коэффициент
по ним не подбирается; вариант без усадки не исполняется как новая policy.
Поля `correction`/`unshrunk` внутри action имеют единицы PDM; поля с `_pp` —
процентные пункты. Повтор использует проверенный audit commit. При изменении
кода аудита нужен отдельный `--out`, исходные commit-файлы удалять нельзя.
