# Проверка влияния обученных голов

В двух опасных заменах компонентный MLP предсказал значительное улучшение
удержания полосы, хотя измеренная метрика равна 1 у baseline и у кандидата.
В одном случае модель также поменяла знак относительного DAC. Это мотивирует
проверку готовых прогнозов на всех 651 training-сценах.

После commit/push/pull, внутри контейнера:

```bash
cd /workspace/DriveSuprim
bash scripts/drivesuprim/evaluation/run_selector_component_heads.sh check &&
bash scripts/drivesuprim/evaluation/run_selector_component_heads.sh audit \
  > /workspace/exp_v2/selector_component_heads_v1.log 2>&1 &&
cat /workspace/exp_v2/drivemem_memory/experiments/component_heads_audit_v1/report.json
```

Обучения, новых меток, scorer calls и загрузок нет. GPU не требуется. PyTorch
из существующего контейнера используется только для точного воспроизведения
sigmoid учителя; локальные тесты NumPy-аудита не требуют установки PyTorch.

Проверяются 11 вариантов × два прежних режима (raw и gain_m020):

- student — полное воспроизведение компонентного MLP;
- teacher — полное воспроизведение контроля без обучения;
- восемь вариантов с возвратом ровно одной головы к прогнозу учителя;
- совместный возврат DAC и удержания полосы для проверки их взаимодействия.

Замена применяется к baseline и всем 16 кандидатам во всех seed, а не только
к двум известным ошибкам. Сначала заново вычисляются per-seed scores/gains,
затем усредняются компоненты и пересчитывается ensemble score и gain_lower.
Разброс seed не сохраняется искусственно от исходного MLP. Никаких новых
порогов или подборов доли смешивания нет.

Проверяются hashes исходного эксперимента и bundle, принадлежность OOF-прогнозов
целым исключённым поездкам и точное восстановление исходного MLP-ансамбля.
Решения student/teacher обязаны воспроизвести старые решения. Все новые решения
сохраняются до оценки измеренных исходов. Несовпадение останавливает аудит.

В отчёте есть gain macro/micro, bootstrap по поездкам, число замен и ухудшений,
худшая потеря и парная разница с исходным student. Отдельно считаются старые
опасные сцены, где ухудшение осталось/исчезло, и новые опасные сцены. Исправить
два примера ценой новых ошибок в других местах не считается улучшением.

Выходы: `report.json`, `decisions.json`, `per_scene.csv`,
`source_harm_cases.csv`, `identity.json` в
`/workspace/exp_v2/drivemem_memory/experiments/component_heads_audit_v1`.
В CSV есть предсказанные и измеренные изменения всех компонентов.

Это исследовательская абляция после просмотра training OOF ошибок. Даже
положительный результат не доказывает независимое преимущество. Автоматического
выбора победителя нет: `selection_performed=false`, исходный primary сохраняется.
Четыре отложенные поездки остаются закрытыми.

Пути можно изменить через `--source`, `--bundle`, `--out`. Повторный запуск
проверяет готовые артефакты; изменение входов или кода требует нового out root.
