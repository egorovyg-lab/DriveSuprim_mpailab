# Прямой выбор Drex из всех 256 кандидатов

Новая гипотеза: Drex одновременно видит весь предложенный DS пул из 256
траекторий и выбирает одну. Это не попарный алгоритм, не турнир, не
обучаемый селектор и не уточнение первого выбора DS.

Каждый запрос содержит текущее движение ego (vx, vy, ax, ay) и таблицу:

- восемь абсолютных sigmoid-прогнозов DS: NC, DAC, DDC, TLC, progress, TTC,
  lane keeping, history comfort;
- x/y через 1, 2, 4 секунды, конечный heading;
- длина, максимальная скорость, абсолютное ускорение и кривизна.

Геометрия номинальная, с шагом исходных поз 0.1 с. Ускорение учитывает
переход от измеренной текущей скорости, кривизна не считается по шагам
меньше 0.05 м. Числа округлены до четырёх десятичных знаков, как в прежней
табличной серии. Полных 40 поз в тексте нет — выбран формат точек 1/2/4 с.

Нет фотографий, карт, будущих участников, симулированных исходов,
итогового балла DS, imitation, ранга DS, обозначения его первого выбора
или разностей относительно него. Только анонимные ID и абсолютные числа.
ID и порядок определяются отдельно от DS-оценок и измеренных исходов.

Основной результат — одиночный ответ на общий список из 256 вариантов
в зафиксированном перемешанном порядке. Обратный порядок — отдельная
диагностика устойчивости, не голосование и не выбор лучшего результата.
Раньше общие таблицы ограничивались top64 и содержали score/imitation;
данная комбинация полного пула и удалённых подсказок отличается от них.

## Сначала технический пилот

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_DIRECT256_NAME=direct256_absolute_gpu2_v1
bash "$HOME/drivesuprim/scripts/drex/run_direct256.sh" submit-pilot 2
```

Поддержаны 1, 2, 4, 8 GPU: одна Slurm allocation, одновременные workers,
одна копия Drex на каждой GPU. Число GPU и имя фиксируются для продолжения.
Для другого числа используйте отдельное имя. На GPU требуется BF16 и >=70 GiB.
После `Submitted batch job` терминал можно закрыть. Лимит пилота — 1 час,
полного запуска — 8 часов; RAM запрашивается по 96 ГБ на worker. Это лимиты
планировщика, не прогноз фактической длительности. GPU используются как
реплики для разных запросов, контекст одного запроса между GPU не делится.

Перед моделью выполняются unit-тесты и собираются входы для всех 651 TRAIN-сцен.
Технический пилот — четыре сцены из разных сессий, всего восемь запросов
с двумя порядками. Схема запроса доступна в `preview_request.json`.

Предел запроса — не больше 65 536 токенов и не больше заявленного
`max_position_embeddings`, если он найден в конфиге. Реальная пригодность
этой длины для официального noncausal Drex не предполагается заранее:
пилот проверяет prepare и forward на A100. Достижение лимита контекста
считается возможной обрезкой и останавливает запуск. Ответ обязан содержать
ровно 256 конечных вероятностей с корректной суммой. Ошибка подготовки,
ограничение формата или CUDA OOM сохраняются в `workers/*/failure.json`.
Пул не сокращается и текст не обрезается для получения ответа.

```bash
bash "$HOME/drivesuprim/scripts/drex/run_direct256.sh" status 2
```

Логи: `/scratch/pr0201/drex_runtime/logs/direct256-pilot-JOBID.log` и
`direct256-worker-JOBID-RANK.log`. Проверять нужно `pilot_report.json` и
ошибки workers. Статус `pilot_complete` означает технический успех,
не качество управления.

## Полный выбор после успешного пилота

```bash
bash "$HOME/drivesuprim/scripts/drex/run_direct256.sh" submit-full 2
```

Всего 1302 запроса для 651 сцены. Завершённые запросы сохраняются с привязкой
к входам. При повторном запуске с тем же именем/числом GPU они проверяются
и повторно не считаются; несовпадение научного кода или входов требует
нового имени. Исторические эксперименты не изменяются.

Результаты: `/scratch/pr0201/drex_runtime/runs/direct256_absolute_gpu2_v1/`.
`decisions.json` фиксирует выборы и SHA результатов, `report.json` содержит
статус `choices_complete`, число сцен и смен выбора при изменении порядка.

## Как будем оценивать

Этот запуск **не читает реальные метрики** и не объявляет улучшение PDM.
Сначала фиксируем все решения. Для сравнения с DS требуется отдельный скоринг
выбранных траекторий: в существующей полной оценке метки есть только для top64.
Кандидат вне top64 имеет неизвестный исход, а не нулевой PDM. Оценка только
совпавшей с прежними метками части будет смещённой и не заменит полную.
На следующем шаге достаточно досчитать выбранных кандидатов и исходный DS;
oracle по всем 256 потребовал бы отдельного полного скоринга.

Все 651 сцена относятся к ранее изученному TRAIN. Это исследовательская
проверка новой гипотезы, без обучения Drex, открытия holdout или заявления
о безопасности автомобильного контроллера.
