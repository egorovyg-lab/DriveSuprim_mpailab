# Разбор ошибок после teacher veto

Этот этап отвечает на два вопроса: почему 14 замен `mlp/gain_m020/all5_pre`
не улучшили PDM и какие ограничения учителя отсеивают хорошие альтернативы.
Используются только готовые training top16-метрики, прогнозы и решения.
Обучения, GPU, новых scorer calls и загрузок нет. Четыре fresh holdout закрыты.

После commit/push/pull, внутри контейнера:

```bash
cd /workspace/DriveSuprim
bash scripts/drivesuprim/evaluation/run_selector_veto_audit.sh check
bash scripts/drivesuprim/evaluation/run_selector_veto_audit.sh audit \
  > /workspace/exp_v2/selector_veto_audit_v1.log 2>&1
cat /workspace/exp_v2/drivemem_memory/experiments/teacher_veto_audit_v1/report.json
```

Прежние файлы экспериментов остаются неизменными. Проверяются их hashes,
воспроизведение четырёх режимов для `mlp/gain_m020`, исходы raw/filtered и
согласованность с предыдущим отчётом о доступных альтернативах.

В новом каталоге `teacher_veto_audit_v1` сохраняются:

- `report.json`: причины потерь по измеренным компонентам, сравнение pre/post,
  статистика каждого запрета и точных пересечений запретов.
- `primary_interventions.csv`: все замены фиксированного варианта; прогнозы
  критика, DAC и других голов учителя, baseline/выбранные raw и filtered метрики.
- `candidate_diagnostics.csv`: все 9765 альтернатив из training top16,
  измеренные изменения и нарушения относительных ограничений учителя.
- `constraint_opportunity_per_scene.csv`: потенциал отдельно каждого запрета,
  всех пяти и всех пяти без одного конкретного ограничения.
- `pre_vs_post_per_scene.csv`: что изменил выбор запасной траектории вместо
  возврата к baseline после отклонения исходного решения.

Полезная альтернатива: выигрыш stored raw PDM не менее 0,5 п.п. и ни один из
пяти измеренных safety-компонентов не хуже baseline. Baseline в подсчёт
альтернатив не входит. Допуски совпадают с предыдущим этапом.

Покомпонентные количества пересекаются, их нельзя складывать. В
`exact_veto_patterns` каждая альтернатива учитывается ровно один раз. Поле
`recovered_useful_scenes_if_only_this_constraint_removed` считает сцены, в
которых все пять запретов исключили все полезные альтернативы, а удаление
только указанного ограничения восстанавливает хотя бы одну.

Raw PDM не пересчитывается по компонентам. Если filtered-метрики отличаются
при прежнем score, это явно отмечается. Падения отдельных компонентов описывают
сопутствующие изменения; это не точное разложение нелинейной формулы PDM.
Потеря score без падения какого-либо сохранённого компонента получает отдельный
флаг и требует проверки согласованности данных до новой модели.

Снятие одного запрета здесь — описательный oracle-аудит, а не подбор новой
политики. Метод, пороги и `primary` не меняются. Результаты относятся к уже
просмотренным training OOF данным и не служат независимым подтверждением.

Для иных путей поддерживаются `--veto`, `--night`, `--bundle`, `--out`.
Повторный запуск проверяет готовый отчёт и его hashes. Изменение входов или
кода требует нового `--out`.
