# Независимая оценка траекторий Drex

Один запрос содержит одну траекторию, текущее движение автомобиля и вопрос
с двумя ответами: `SUITABLE` или `UNSUITABLE`. Вероятность первого ответа
служит оценкой для ранжирования. Во входе нет ранга, оценок компонентов
или итогового балла DriveSuprim.

Для каждого кандидата есть два режима. `road` показывает проекцию линии
на текущем переднем кадре, `blank` показывает ту же линию на белом фоне.
В обоих случаях нижняя часть картинки содержит одну и ту же полную схему
с отметками 1–4 с. Масштаб фиксирован на сцену по всем 64 траекториям.
Проекция использует существующий рендер v2 с плоской землёй и ограниченной
областью линзы. Если часть линии вне этой области, нижняя схема показывает
всю траекторию.

Один набор оценок позволяет выбрать максимум как среди первых 16
по исходному рангу DS, так и среди всех 64. При равенстве побеждает кандидат
с более высоким рангом DS. Получаются четыре метода на 651 TRAIN-сцене,
всего 83 328 запросов, включая пилотные. Пилот выполняет 128 запросов на
8 сценах из разных сессий с кандидатами по всему диапазону рангов.

## Запуск на msu270

Одна задача Slurm запрашивает один узел и 1, 2, 4 либо 8 GPU. На каждой GPU
работает отдельная реплика. Число GPU, имя запуска, план и версии кода
фиксируются для продолжения.

Из PowerShell в локальном checkout перенесите три файла:

```powershell
scp scripts/drex/pointwise.py scripts/drex/run_pointwise.sh scripts/drex/test_pointwise.py pr0201@10.36.60.202:drivesuprim/scripts/drex/
```

Из серверного checkout запустите пилот:

```bash
cd ~/drivesuprim
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_NODE=auto
bash scripts/drex/run_pointwise.sh submit-pilot 4
bash scripts/drex/run_pointwise.sh status 4
```

После `pilot_complete` команда `resume 4` продолжает полный прогон.
`submit-night 4` выполняет пилот и полный прогон в одной задаче. Парные
оценки кандидатов сохраняются атомарно. При истечении времени команды
`resume 4` можно повторять до `choices_complete`. Если прервался сам
пилот, повторите `submit-pilot 4`. Лимит полного прогона по умолчанию
8 ч, его можно изменить переменной `DREX_POINTWISE_TIME`. В статусе
воркеров есть счётчики и время текущей попытки. Отчёт пилота показывает
медианную длительность вызова модели для обоих режимов. Она не включает
чтение и рендер изображений, запись чекпоинтов и загрузку модели.

По умолчанию файлы находятся в
`$DREX_RUNTIME_ROOT/runs/pointwise_gpu4_v1`. Две картинки
`preview-blank.png` и `preview-road.png` показывают совпадение разметки.

## Оценка

Скачайте `plan.json`, `report.json` и `decisions.json` из завершённого
прогона в один локальный каталог. В локальном checkout с Python и
зависимостями выполните:

```powershell
python scripts/drex/pointwise.py evaluate `
  --out 'D:\DriveSuprim_mpailab\results\pointwise_gpu4_v1' `
  --astra 'D:\DriveSuprim_mpailab\results\drex_oracle651_v2'
```

Оценка сверяет хеши решений, физические ID траекторий, сессии и ранг в
готовых исходах Astra. В `evaluation.json` будут сравнения с DS, парные
разницы `road − blank` и `top64 − top16`, интервалы по сессиям, изменения
PDM, прогресса, рывка и бокового ускорения. `per_scene.csv.gz` сохраняет
выборы и исходы по сценам. Результат относится к ранее изученному TRAIN.
