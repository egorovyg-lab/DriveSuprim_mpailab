# Прямой выбор Drex из top255 DS

Отдельный протокол `direct255_absolute_v1`. Согласованное изменение исходной
гипотезы direct256: официальный readout имеет 255 выходов, поэтому исключается
ровно последний кандидат стабильного сортирования исходных `selection_scores`
по убыванию. При равенстве сохраняется порядок исходных local IDs. Исходный
выбор DS обязательно остаётся в пуле. Обучения головы/модели нет.

В Drex поступают текущие vx/vy/ax/ay и 255 строк абсолютных признаков:
8 sigmoid-прогнозов DS; x/y на 1/2/4 с; конечный heading; длина;
максимальные скорость, абсолютное ускорение и кривизна. Геометрия номинальная,
без исполнения контроллером. Используется прежняя математика direct256.
Ранг, итоговый балл, imitation, baseline flag, разности, изображения, карты,
симулированные исходы и будущие участники не передаются. Балл DS используется
только снаружи модели, чтобы определить top255. Порядок анонимных вариантов
не зависит от рейтинга DS. pool_selection.json фиксирует исключённые ID
и baseline для аудита, но не является частью модельного запроса.

Первичный результат — один ответ для primary-порядка. Reversed — отдельная
проверка чувствительности, без голосования или выбора лучшего по метрикам.
4 сцены из разных сессий дают 8 pilot-запросов; полный набор — 651 TRAIN-сцена
/ 32 сессии, 1302 запроса. Данные и код фиксируются SHA до вызовов модели.

## msu270

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_NODE=auto
export DREX_DIRECT255_NAME=direct255_absolute_gpu4_v1
bash scripts/drex/run_direct255.sh submit-pilot 4
```

1/2/4/8 GPU поддержаны. Один job на одном узле, по копии BF16-модели на каждую
GPU, одновременные srun workers с разными устройствами. Это реплики, контекст
одного запроса не распределяется между GPU. RAM — 96 GiB на worker.
Число GPU и имя сохраняются при продолжении. GPU должны поддерживать BF16 и
иметь >=70 GiB памяти. Подтверждены короткие smoke-тесты; пригодность большого
255-way запроса ещё проверяет пилот.

Статус и диагностика:

```bash
bash scripts/drex/run_direct255.sh status 4
squeue -u "$USER" -o "%.18i %.30j %.10T %.10M %R"
```

Пилот имеет лимит 1 час. Лог coordinator:
`$DREX_RUNTIME_ROOT/logs/direct255-pilot-JOBID.log`;
workers: `direct255-worker-pilot-JOBID-RANK.log`.
В каталоге runs/$DREX_DIRECT255_NAME: preview_request.json, inputs/,
pool_selection.json, workers/RANK/status.json, pilot_report.json.

При `pilot_complete` можно подать полный расчёт:

```bash
bash scripts/drex/run_direct255.sh submit-full 4
```

Или оставить всю цепочку на ночь в одной allocation:

```bash
bash scripts/drex/run_direct255.sh submit-night 4
```

`submit-night` сначала запускает unit-тесты, план и pilot, затем проверяет
его полный отчёт и только после успеха начинает full. Ошибка прекращает
цепочку (`set -e`, `--kill-on-bad-exit=1`). Не подавать одновременно pilot/full/
night с тем же именем: coordinator защищён file lock, лишний job завершится.
После sbatch терминал можно закрыть. Лимит full/night — 8 часов, это не ETA.
Если нужны продолжения, повторить submit-full с теми же именем и count после
остановки предыдущей задачи (при незавершённом pilot — submit-night).

Запросы не обрезаются: cap min(65536, model max_position_embeddings), вход
на границе cap отвергается; OOM/неверный ответ сохраняется как ошибка.
Требуются ровно 255 конечных вероятностей с правильной суммой.
Результаты фиксируются отдельными JSON+SHA receipts в общем results/.
Завершённый pilot переиспользуется в full независимо от rank исполнителя;
незавершённый JSON без receipt пересчитывается, повреждённый receipt останавливает
запуск. Бюджет worker — 7 часов перед очередным запросом, затем требуется resume;
непрерываемый длинный forward всё ещё может достичь общего лимита Slurm.

## Интерпретация

`report.status=choices_complete`, scenes=651, requests=1302 означает готовые
выборы, а не выигрыш PDM. decisions.json содержит физические local/vocab IDs
и SHA результатов. Исходы не читаются до фиксации решений.

Следующий отдельный шаг — оценить все выбранные траектории на Astra с DS
и простыми контролями. При готовом oracle651 можно использовать уже измеренные
исходы; иначе нужны измерения выбранных кандидатов вне прежнего top64.
Для сравнения на одинаковом пуле контроли также ограничиваются top255;
прежние результаты контролей на 256 сохраняются отдельно.
Oracle255 нужно считать отдельно от oracle256, исключив тот же rank256:
исходная oracle256 — верхняя граница другого, чуть большего пула. Не выбирать
порядок/правило по итоговым метрикам. Все 651 сцена ранее изученного TRAIN;
свежий holdout не открывается, local PDM не равен полному EPDMS.
