# Проверка линии, уходящей в небо

В превью v1 обнаружена голубая линия, пересекающая дорогу и небо. Такое превью
не подтверждает правильное совмещение с дорогой. Число видимых сегментов
проверяет только пересечение с прямоугольником изображения.

В исходном `project` проверяются положительная глубина, конечность пикселей
и ненулевой знаменатель дисторсии. Это допускает другой участок полинома
Brown–Conrady: близкая к камере точка земли может отобразиться над горизонтом.
Это воспроизводится тестом с отрицательным первым радиальным коэффициентом.
Причину артефакта на реальной сцене ещё требуется подтвердить её калибровкой.

Требование монотонности/биективности описано в
[официальной документации OpenCV](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).
Полином нельзя без проверки экстраполировать на любые направления вне
рабочего поля зрения объектива. Простое удаление линии выше некоторой строки
или отключение дисторсии не устанавливает правильную геометрию.

## Запуск

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_OVERLAY_NAME=overlay_top4_gpu4_v1
bash scripts/drex/run_overlay_audit.sh submit
```

Одна CPU-задача Slurm, без GPU/обучения/инференса. После получения JobID можно
отключаться. Лог: `$DREX_RUNTIME_ROOT/logs/overlay-audit-JOBID.log`.
Проверка читает только входы существующего плана: калибровку, изображения,
словарь траекторий и разрешённые поля исходных кандидатов DS. Метки PDM и
результаты Drex не десериализуются.

Выходы в существующем каталоге серии, в отдельной подпапке
`projection_audit_v1/`:

- `report.json`: количество сцен/сегментов с обнаруженными нарушениями;
- `per_scene.json`: полная калибровка, скорость, длины/концы top4-путей,
  исходная видимость и диапазоны подозрительных сегментов;
- `TOKEN-trace.csv`: точки пути, время, глубина, пиксели, радиальный множитель,
  его производная, определитель якобиана и диагностические флаги;
- `TOKEN-ID-diagnostic.png`: первые четыре сцены. Пурпурный цвет отмечает
  подозрительные сегменты исходного рендера, голубой — остальные исходные
  сегменты. Голубой не означает подтверждённую правильность проекции.

Первый ноль/полюс/поворот радиального отображения задаёт границу его ветви,
связанной с оптической осью. Дополнительно проверяется локальный якобиан
полного отображения с тангенциальными коэффициентами. Эти проверки ищут
ошибки, но не сертифицируют калибровку, глобальную биективность или плоскость
дороги. Ноль обнаруженных нарушений сам по себе не разрешает принимать
геометрию.

Исходные `overlay_data.py`, `overlay_pilot.py`, `run_overlay.sh`, план, превью,
пилотные ответы и решения не меняются. Диагностические изображения не подаются
модели. Исправленная геометрия потребует отдельной версии протокола/каталога
и новых запросов; старые ответы нельзя переиспользовать с новыми пикселями.
