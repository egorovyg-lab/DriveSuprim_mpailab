# Astra: контролы на 651 сцене и oracle256 на 64 сценах

Запуск CPU, Python 3.9, без новых изображений, GPU, обучения или вызовов Drex.
Используется существующий контейнер `egorov_drivesuprim` и проверенные исходные
метаданные/кеши из portable package. Нужен завершённый
`/workspace/exp_v2/drex_rollout_audit/rollout_audit_pool64_v1` со старыми tools.
Новое исследование не меняет код scorer и старые результаты.

## Что будет сделано

1. Для всех 651 TRAIN-сцен: исходный DS, DS без финального imitation и
   фиксированная head-only формула на округлённых до 4 знаков прогнозах —
   том же представлении прогнозов, которое получает direct256 Drex.
2. Для 64 сцен: по две из каждой из 32 сессий, выбор по фиксированному seed
   и token/session metadata, без использования исходов. Измеряются все 256
   кандидатов, существующие top64 повторно используются после SHA-проверки.
3. Oracle16/64/256 по PDM, относительной безопасности компонентов и комфорту
   с прежним строгим `geometry_peaks` допуском и бюджетом прогресса 1 м/5%.
   Это верхние границы по известному будущему, не deployable алгоритмы.

Head-only proxy: произведение прогнозов NC/DAC/DDC/TLC, умноженное на
`(5 progress + 5 TTC + 2 lane + 2 history comfort)/14`.
Это некалиброванный контроль по прогнозам, не восстановленный реальный PDM.
Равенства разрешаются по ID словаря без обращения к выбору DS.

Для удаления imitation сначала численно воспроизводится сохранённая формула
navsim_v1 или navsim_v2 с/без imitation. Неоднозначность или несовпадение
останавливают эксперимент. Пул 256 остаётся исходным: этот контроль не
отменяет imitation-отбор на более ранних стадиях 8192 → 256.

Решения контролов и набор сцен фиксируются до чтения меток. На каждой сцене
повторно симулируется DS и проверяется совпадение исходных 9 raw-компонентов
и непрерывных метрик. Для новых кандидатов исходы неизвестны: они измеряются
заново, а не заполняются нулями. Каждая симуляция получает свежую копию кеша.

## Получение кода на Astra без переключения рабочей ветки

На **хосте Astra** открой контейнер:

```bash
docker exec -it -w /workspace/DriveSuprim egorov_drivesuprim bash
```

Следующие команды выполняются **в контейнере**. Fetch обновляет Git refs, но
не переключает ветку и не меняет scorer/файлы checkout. Экспортируются только
три новых инструмента, отдельно от старого рабочего репозитория.

```bash
cd /workspace/DriveSuprim
git fetch origin codex/drex-max
TOOLS=/workspace/exp_v2/drex_astra_cpu256/controls_oracle64_v1/tools
mkdir -p "$TOOLS"
(
  set -e
  for f in astra_cpu256.py run_astra_cpu256.sh test_astra_cpu256.py; do
    test ! -e "$TOOLS/$f"
    git show "origin/codex/drex-max:scripts/drex/$f" > "$TOOLS/$f"
  done
) && bash "$TOOLS/run_astra_cpu256.sh" start
```

Экспорт инструментов выполняется один раз. После сообщения `launched` можно
закрыть терминал: процесс создан с отдельной сессией и отвязанным stdin/out/err.
Сначала unit-тесты, затем мини-прогон на четырёх сессиях, после успешного
совпадения исходных метрик — автоматически полный расчёт.
Лимита в семь часов нет; результаты новых кандидатов сохраняются отдельно
и продолжаются после остановки. Повторный `start` с тем же каталогом
использует проверенные результаты, одновременный расчёт блокируется.

Статус, снова в контейнере:

```bash
bash /workspace/exp_v2/drex_astra_cpu256/controls_oracle64_v1/tools/run_astra_cpu256.sh status
```

Лог: `/workspace/exp_v2/drex_astra_cpu256/controls_oracle64_v1/run.log`.
При ошибке сначала изучить `failure.json`/лог; код и входы заморожены,
изменённый протокол требует отдельного каталога, не удаления identity.

## Что анализировать

В каталоге `controls_oracle64_v1`: `report.json`, `per_scene.csv.gz`,
`per_candidate.csv.gz`, `request.json`, `identity.json`.
Методы `baseline`, `no_final_imitation`, `absolute_head_proxy` относятся ко
всем 651 сценам. Префикс `control64/` — те же контролы на тех же 64 сценах,
что oracle. Не сравнивать агрегат oracle64 с контролами на другой выборке.
Нужно смотреть выигрыш PDM, компонентные ухудшения, комфорт, прогресс,
количество meaningful улучшений и разброс по сессиям.
Все сцены уже исследовались, свежий holdout не открывается. Local PDM не EPDMS.

## Будущие решения Drex

Когда появится полный `decisions.json` direct256 на 651 сцене, скопируйте его
в контейнер. Используйте **новый** каталог результата:

```bash
export ASTRA_CPU256_ROOT=/workspace/exp_v2/drex_astra_cpu256/with_drex_v1
export ASTRA_CPU256_DECISIONS=/absolute/path/to/decisions.json
bash /workspace/exp_v2/drex_astra_cpu256/controls_oracle64_v1/tools/run_astra_cpu256.sh start
```

Требуются оба порядка, ровно 651 token, уникальные пары и совпадение
candidate_local/candidate_vocab с исходным 256-пулом. Обратный порядок
оценивается отдельно, не выбирается лучший по результату скоринга.
В этом режиме oracle заново не считается: только выбранные кандидаты,
DS и два контроля. Файл решений фиксируется SHA. Измерения вне top64
выполняются обязательно; оценка по одной совпавшей с top64 части не выдаётся
за полную. Для последующих исследований произвольных новых сцен этот
инструмент не предназначен — он проверяет именно зафиксированный TRAIN-набор.
