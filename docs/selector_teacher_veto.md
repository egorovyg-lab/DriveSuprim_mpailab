# Относительный запрет по прогнозам DriveSuprim

У двух критических DAC-пропусков исходный teacher прогнозировал ухудшение DAC
примерно на .139 и .105, а learned critic оценивал риск как .0048 и .0012.
Этот диагностический этап проверяет явное сохранение прогнозируемых ограничений
учителя. Правило мотивировано уже просмотренными training OOF ошибками, поэтому
результат является настройкой метода, не независимой проверкой.

После commit/push/pull, внутри контейнера:

```bash
cd /workspace/DriveSuprim
bash scripts/drivesuprim/evaluation/run_selector_teacher_veto.sh check
bash scripts/drivesuprim/evaluation/run_selector_teacher_veto.sh compare \
  > /workspace/exp_v2/selector_teacher_veto_v1.log 2>&1
cat /workspace/exp_v2/drivemem_memory/experiments/teacher_veto_v1/report.json
```

Используются все 651 train-сцена, сохранённые OOF ансамбли linear/MLP и прежние
исходы top16. Новых моделей, scorer calls, изображений или GPU не требуется.
Готовые эксперименты читаются без изменения. Четыре fresh holdout не открываются.

Для четырёх заранее перечисленных host policies (gain margins .005/.02 и те же
margins с risk limit .05) проверяются четыре режима:

- `original`: точное воспроизведение исходного решения.
- `dac_post`: выбранная альтернатива отклоняется при снижении teacher DAC.
- `all5_post`: альтернатива отклоняется при снижении любого из NC/DAC/DDC/TLC/TTC.
- `all5_pre`: тот же запрет по всем пяти прогнозам применяется до argmax, чтобы
  можно было выбрать другой допустимый кандидат вместо возврата к baseline.

Сравниваются sigmoid-прогнозы compliance относительно baseline. Допуск 1e-6
служит численной погрешности, не подбирается по двум ошибкам. Прогнозы учителя
могут быть неверны; это условие не гарантирует измеренную безопасность. Оно
также способно отбрасывать хорошие альтернативы — например, если teacher
недооценил реально безопасный манёвр.

Поэтому отчёт `oracle_opportunity` отдельно показывает, сколько измеренного
потенциала остаётся после ограничений и сколько сцен ещё имеют полезную
альтернативу. Это описательная оценка доступности кандидатов с использованием
outcomes, а не deployable oracle. В выборе кандидата measured labels не используются.

Один кандидат для следующего этапа зафиксирован до запуска: **MLP/gain_m020/all5_pre**.
Автоматического выбора лучшего из всех вариантов нет. DAC-only остаётся
диагностикой. Для кандидата используются прежние критерии ночного эксперимента:
положительный uniform macro gain, zero observed harm, максимальная одиночная
потеря не более 5 п.п., минимум 10 замен в трёх поездках и полезные улучшения
хотя бы в трёх поездках. При невыполнении критериев primary=baseline.

Перед оценкой проверяются hashes ночных артефактов и bundle. Исходные решения
должны точно воспроизвестись. Все новые решения сохраняются в `decisions.json`
до чтения измеренных результатов для оценки. Новые отчёты: `report.json`,
`per_scene.csv`, `opportunity.csv` в `experiments/teacher_veto_v1` внутри
`/workspace/exp_v2/drivemem_memory`. Для иных путей есть CLI options `--night`,
`--bundle`, `--out`. Изменение протокола/входов требует нового output root.
