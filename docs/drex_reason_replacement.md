# Drex: причина замены траектории

Офлайн-эксперимент на прежних 651 TRAIN-сценах. Для каждой сцены фиксируется
пара из исходного выбора DriveSuprim и одной альтернативы top16 DS. Берём
самую сильную альтернативу по прежней формуле контроля `absolute_head_proxy`,
отдавая приоритет кандидатам без ухудшения прогнозов пяти компонентов
безопасности и с потерей прогнозируемого прогресса не более 0,01 по шкале 0–1.
Если таких кандидатов нет, берём максимальный proxy для диагностики. Правила
основной оценки в этой сцене сохранят DS. Все пороги фиксированы до запуска.

Основной вопрос предлагает сохранить DS или назвать одну причину для замены:
столкновения, проезжая зона, направление, светофоры, TTC, прогресс, полоса
или исторический комфорт. Бинарный контроль видит те же входные числа и
сравнивает `KEEP` с `REPLACE`. Каждому вопросу соответствует прямой и обратный
порядок вариантов ответа. Порядок строк и роли двух траекторий остаются
фиксированными. Входы используют прогнозы DS, номинальные параметры траекторий
и текущее движение. Камеры в этой версии не подаются.

Основное правило заменяет DS, когда оба порядка дают одну и ту же конкретную
причину и числовая проверка не обнаружила ухудшения прогнозов безопасности или
выхода за бюджет прогнозируемого прогресса. Бинарный контроль использует ту же
проверку и требует двух голосов за замену. Числовой контроль использует ту же
проверку и требует выигрыша по `absolute_head_proxy`. Дополнительно сохраняется
диагностический результат одного ответа с причиной без этих ограничений.

## Запуск на msu270

```bash
cd ~/drivesuprim
git pull --ff-only
export DREX_RUNTIME_ROOT=/scratch/pr0201/drex_runtime
export DREX_NODE=auto
bash scripts/drex/run_reason_replacement.sh submit-night 2
```

Одна Slurm allocation и одна реплика на каждую GPU. Поддерживаются 1, 2, 4 и 8
GPU. После тестов запускаются пилот на четырёх сценах из разных сессий
(16 запросов) и полный прогон (2 604 запроса с учётом результатов пилота).
Отдельный пилот можно подать через `submit-pilot 2`, а продолжение через
`submit-full 2`. Продолжение сохраняет число GPU, имя запуска и план. При
сбое до отчёта пилота повторите `submit-night` с теми же аргументами.

```bash
bash scripts/drex/run_reason_replacement.sh status 2
squeue -u "$USER"
```

Путь по умолчанию — `$DREX_RUNTIME_ROOT/runs/reason_replacement_gpu2_v1`.
`choices_complete` означает, что все решения зафиксированы и готовы к оценке.

## Оценка с готовыми исходами Astra

Скопируйте `plan.json`, `report.json` и `decisions.json` из одного запуска в
локальный каталог. Пример для Windows PowerShell:

```powershell
$dest = 'D:\DriveSuprim_mpailab\results\reason_replacement_gpu2_v1'
New-Item -ItemType Directory -Force $dest | Out-Null
$src = 'msu270:/scratch/pr0201/drex_runtime/runs/reason_replacement_gpu2_v1'
scp "$src/plan.json" "$src/report.json" "$src/decisions.json" "$dest"
```

В рабочей копии ветки:

```powershell
python scripts/drex/reason_replacement.py evaluate --out $dest `
  --astra D:\DriveSuprim_mpailab\results\drex_oracle651_v2
```

Для оценки нужны `request.json`, `report.json` и `per_candidate.csv.gz`
завершённого `oracle651_v2`. Скрипт сверяет хеши плана и решений, совпадение
пакета, ID сцен, сессий, локальные ID, ID словаря и ранги. Повторная симуляция
не требуется. `evaluation.json` содержит парные интервалы по сессиям, долю
замен, потери прогресса, PDM, RMS рывка и бокового ускорения, ухудшения отдельных
компонентов и проверку каждой принятой причины. Причина подтверждается, если
соответствующий измеренный компонент улучшился. Для причины «прогресс» также
нужен прирост измеренного продвижения хотя бы на 0,5 м. Полезная замена имеет
выигрыш PDM от 0,5 п.п., сохраняет остальные компоненты и теряет не больше
1 м и 5% измеренного продвижения одновременно. Для сравнения при одинаковой
доле замен оставляем самые уверенные вмешательства каждого метода по его
собственным оценкам, без подбора количества по PDM. Отчёт относится к ранее
изученному TRAIN-набору.
